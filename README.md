# KarmaFlow（Android）

KarmaFlow 是一款完全本地运行的私人预算与短信记账 App。它监听银行短信，在手机上解析收支、退款、账户余额和银行名称，并将结果写入本地 Room 数据库。应用不上传账目，也不保存完整短信正文。

- 当前版本：`1.21.0`（`versionCode 28`）
- 应用包名：`com.example.sizhang`
- 技术栈：Kotlin、Jetpack Compose、Room、DataStore、WorkManager
- 最低 Android 版本：Android 8.0（API 26）
- 目标 Android 版本：Android 15（API 35）

## 短信自动记账

- 识别快捷支付、POS 消费、转账支出、手机银行转出、ATM/柜面取款、代扣、短信服务费、理财申购和信用卡自动还款支出。
- 识别转账汇入、工资代发、柜面存入、理财赎回、结息等收入；收入不会计入消费统计。
- 识别退款、POS 退货、交易冲正、撤销和退回，并从净消费中扣除。
- 过滤验证码、动态口令、失败交易、登录提醒和不含明确支出字样的普通还款通知。
- 支持中国银行信用卡外币消费，例如 HKD；外币交易保留原币种，不混入人民币预算。
- 使用 SHA-256 短信指纹和 Room 唯一索引双重去重，补扫历史短信不会重复记账。
- 首页显示最近一次短信接收和解析状态，但不显示或保存完整短信正文。

## 多卡账户

- 每家银行固定显示为一个账户，不识别或展示卡尾号。
- 同一家银行有多张卡时，交易都会归入该银行账户；余额采用该银行最新一条带余额短信的数值。
- 左侧侧栏只有在识别到账户后才显示“银行账户”区域；没有账户时不显示。
- 首页默认显示已识别银行卡的合计余额。
- 用户可以手动设置总余额；手动值会保留到时间更新的银行短信到达。
- 旧版本升级时 Room 数据库会自动迁移，不会清空原有交易；历史上的多卡账户会在界面中按银行合并。

## 预算与预测

- 预算完全按当前银行卡合计余额计算，不再设置或使用“每周期总预算”。
- 周期起始日期和终止日期均可编辑；默认预留项目为房租 2,400 元、租车 300 元，项目可新增、改名、改金额或删除。
- 支持设置用于原计划对比的周期起始余额和目标结余；目标结余不设预算上限，也不会被分配到每日可花额度。
- 显示今日已消费、本周期净消费、周期剩余和今日可用。
- “今日可用”在当天保持锁定，第二天再按照最新余额、目标结余和剩余天数重新计算。
- “今日可用”卡片提供手动刷新按钮，经确认后可立即按最新余额重新锁定当天额度。
- 当目标结余与预留金额高于当前余额时，今日可用、明日预计可花和消费预览允许显示负数。
- “明日预计可花”根据当天实时消费动态预测第二天额度。
- 独立的“今日消费预览”卡片提供 `¥0–¥2,000` 滑块和可编辑金额，只改变预览结果，不修改真实账目。
- 首页底部显示当前周期最近 31 天的“每日预计花费 / 每日实际花费”双曲线。
- 首页主要金额变化带有平滑数字动画。

## 历史收支明细

- 首页最下方按时间倒序显示全部本地收入、支出与退款，包含银行、交易说明、时间、币种和金额。
- 每笔记录都可选择“取消计入”，被取消的记录仍保存在本机，但不再参与今日消费、周期统计和曲线计算。
- 已取消的记录可以随时“恢复计入”；由于短信指纹仍保留，历史补扫不会把它作为新交易重复导入。

## 短信同步机制

1. 新短信到达时，`BroadcastReceiver` 使用 `RECEIVE_SMS` 实时解析。
2. 用户授予 `READ_SMS` 后，应用每次回到前台都会补扫最近 45 天的支持银行短信。
3. WorkManager 会安排周期性安全补扫；Android 可能根据电量和后台策略延迟执行。
4. 左侧侧栏可以随时点击“立即同步”手动补漏。

HyperOS 等系统可能限制后台广播或强制停止应用。即使实时监听被系统延迟，重新打开 KarmaFlow 后也会通过历史补扫恢复遗漏记录。强制停止期间 Android 不允许应用继续监听，这是系统限制。

## 构建与测试

使用 Android Studio 打开项目，建议环境为 JDK 17 和 Android SDK 35。命令行构建：

```text
gradlew.bat testDebugUnitTest assembleDebug
```

生成的调试安装包位于：

```text
app/build/outputs/apk/debug/app-debug.apk
```

当前测试覆盖原有中国银行格式、七家银行代表短信、多币种消费、收入/退款分类、日期解析、余额提取、预算计算和短信去重。

## 隐私与权限

| 权限 | 用途 |
| --- | --- |
| `RECEIVE_SMS` | 实时接收并解析新到达的银行短信 |
| `READ_SMS` | 用户授权后补扫最近 45 天的支持银行短信 |

- 所有短信解析和预算计算均在手机本地完成。
- 数据库只保存结构化交易字段、银行名称、余额和不可逆指纹；新记录不保存卡尾号。
- 不保存完整短信正文，不保存验证码，不保存完整卡号。
- 应用未声明网络权限，不向服务器上传数据。
- 应用关闭系统备份并禁止明文网络流量。

## 已知限制

- 银行短信格式会随地区、卡种、语言和银行系统升级而变化，无法保证所有真实模板都与示例完全一致。
- 同一家银行永远按一个账户显示，因此不会区分该银行下的多张卡。
- 交易短信里的余额通常是交易后的余额；如果银行不发送余额，只能显示“余额待识别”。
- 首次使用建议核对一笔真实交易。如遇到未识别格式，请先隐藏姓名、完整卡号、余额和验证码，再提供脱敏模板以扩展规则。
